# Architecture diagrams

UML diagrams of ABChapterize, rendered to SVG. These are for people working *on* the tool -
end users want [the manual](../manual.md) instead, which describes what the software does rather
than how it is put together.

Each `.svg` here is generated by PlantUML from a matching `.puml` source. Those sources are not in
this repository - like the generator behind the documentation website, they live outside it - so a
clone can read the diagrams but cannot regenerate them. **Never hand-edit an `.svg`**: it is
generated output, and the next regeneration overwrites it without asking.

## Regenerating

Only from a working copy that has the PlantUML sources; they are deliberately not published. The
rendered output is here to be read, and regenerating it is a maintainer's job. The HTML manual is
kept the same way, except one step further: neither its generator nor its output lives here, since
the pages are published at <https://abchapterize.anetos.de> instead.

## These are not in the release archives

The csproj excludes `doc\diagrams\**\*` from the published output, the same way it excludes
`doc\html\**\*`. They live in the repository for people reading the source, and the archive file
count is a release check - so if you add a diagram, nothing about the archives changes.

## Accuracy

The component diagram was derived mechanically from the `using ABChapterize.*` declarations of
every source file, with one distinction applied: a `using` that exists only so a doc-comment
`<see cref>` resolves is documentation, not a dependency, and is excluded. Fifteen such edges were
found and dropped, which is the difference between a readable graph and a hairball.

Everything else was written from the source and its doc comments. The diagrams state design
decisions in the notes attached to them; where a decision has evidence behind it - a measurement,
a dated case - that evidence lives in [`notes\`](../../notes/), not here.
